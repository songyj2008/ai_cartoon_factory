# 视频提示词修正助手（Chrome 扩展）

## v0.4.19 文字任务后台隔离与会话找回

项目发起的 DeepSeek、ChatGPT、豆包文字任务使用扩展创建的后台标签页，不占用用户已有对话。扩展按服务并发上限创建页面，发送后持续按任务编号读取回复；如果标签页转到了其他对话，会先核对网页中的任务请求，再自动返回已绑定的会话，只读恢复，不重复发送。网页视频生成仍按原有前台流程执行。文字任务从扩展领取时起最多等待 900 秒；刷新项目后台并在 `chrome://extensions` 重新加载扩展后生效。正在使用旧内容脚本的页面也需刷新。

## v0.3.52 混合 LLM 调度

项目现在可以为全局或单个功能同时选择多个网页 LLM。只选一个时固定使用该服务；选择多个时，每个独立网页调用会按当前负载分配到所选服务，并记录实际执行服务。任务恢复会继续检查原服务和原会话，不会因为重新分配而重复发送。批量分段提示词可以同时分发给多家服务，并继续遵守每家服务的标签页上限。

## v0.3.51 同服务标签页池

默认每个服务并发 2 项、网页任务合计 6 项；在项目“网页 LLM / Chrome 扩展 → 并行任务与标签页池”中调整（每服务 1–4，总数 1–12）。先打开并登录需要使用的服务，扩展随后复用已有后台页，按排队需求补充后台标签页。每个标签页独占一个任务，后台任务始终新建独立对话；取消、超时后的页面确认空闲才重新分配。降低上限不打断已经运行的任务。普通后台页不抢焦点，冻结页面可能短暂唤醒。重新加载扩展、刷新服务网页并重启项目后生效。同账号多页的实际稳定性取决于网站，尚需在登录账号下观察。

## v0.3.50 跨服务并行任务

项目后台任务按任务编号分别保存和恢复。DeepSeek、ChatGPT、豆包各绑定一个已打开的标签页，不同服务可同时发送和等待；同一服务仍依次执行。手工侧边栏保持一次一个任务，并避开正在执行后台任务的标签页。普通后台标签页不会切到前台；页面被冻结且无法响应时可能短暂唤醒，再恢复原标签页。项目后台任务的 300 秒执行期限从扩展领取时开始，排队时间单独记录。更新后在 `chrome://extensions` 重新加载扩展，并刷新已打开的 LLM 页面。

## v0.3.49 豆包会话按任务信息命名

豆包新会话确认正式会话 ID 后，会使用任务类型、项目简称、集数和目标分段自动重命名，例如 `提示词重生-车间沟通_恒迅工厂_第009集_第006段`。整集任务显示总段数；重命名完成后才记录为已命名。更新后在 `chrome://extensions` 重新加载扩展，并刷新豆包页面。

## v0.3.48 豆包发送确认与单次唤醒

豆包后台标签发出鼠标输入后，不再直接假定已提交；先检查输入框是否清空、任务标记是否进入会话或生成是否开始。若页面仍保留原请求且没有提交证据，只唤醒绑定标签页并补点一次，之后恢复用户原先的标签；第二次仍未确认则暂停点击，避免重复发送。读取阶段不会因轮询反复切换标签。

## v0.3.47 豆包后台标签发送

使用豆包页面已确认的 `button[data-testid="chat_input_send_button"]` 作为发送箭头。发送前由后台校验任务编号、豆包来源、绑定标签页和按钮坐标；标签页未激活时通过 Chrome debugger 鼠标输入点击，不切换浏览器焦点。若无法附加 debugger，则明确报错且不以合成点击或 Enter 代发；输入事件发出后进入等待确认状态，不重复点击。

## v0.3.46 豆包临时会话 ID 修复

豆包新对话会先使用 `/chat/local_...` 临时地址，随后切换成正式会话 ID。扩展现在把临时 ID 视为待确认状态；当正式页面出现同一任务的唯一回复标记时，自动更新绑定并继续读取。临时会话不尝试重命名，待正式 ID 确认后再命名。已绑定正式会话的任务仍禁止仅凭回复标记切到其他会话。

## v0.3.45 豆包会话绑定与命名修正

新对话提交后若豆包延迟换成最终会话地址，扩展会在页面同时包含本任务标记和已提交请求时修正绑定，并读取该回复；仅在原任务确实来自新对话时允许修正，防止串读其他会话。会话历史项没有可识别链接时，改从当前会话右上角菜单尝试重命名为任务 ID。更新后重新加载扩展并刷新豆包页面。

## v0.3.44 豆包会话命名

豆包任务取得独立会话 ID 后，扩展尝试把该会话重命名为提交任务的完整 ID，方便在最近会话中对应任务。只操作 ID 与当前任务绑定的会话；页面菜单无法可靠识别时跳过命名，文字发送和结果读取照常进行。更新后重新加载扩展并刷新豆包页面。

## v0.3.43 豆包任务恢复与结果绑定

豆包后台能响应时直接提交，不切换标签；后台无响应超过 10 秒时才短暂唤醒并恢复同一任务，避免要求手动切换或重复发送。豆包发送后延迟生成对话 URL 时，使用任务唯一标记绑定对话并读取结果，避免错误停在等待进度。每个任务按原策略使用独立新对话；豆包未生成会话标题前，最近列表可能暂时都显示“新对话”。

## v0.3.42 豆包延迟会话绑定与后台提交

豆包在发送后延迟生成对话 URL 时，使用本任务唯一标记绑定新对话并读取结果，避免任务进度停在等待状态。普通后台标签发送和读取不切换焦点；仅 Chrome 明确冻结标签时，首次发送会短暂唤醒，后续读取不会周期性切换。

## v0.3.41 豆包任务不再切换标签

豆包发送和回复检查直接操作绑定的后台标签页，不因标签处于普通后台状态而切换浏览器标签；任务持续轮询原对话结果，不会重复发送。更新后重新加载扩展。

## v0.3.40 豆包后台检查不再反复切换标签

豆包发送和回复检查不再周期性抢焦点；任务在后台检查时不再反复切换标签。更新后重新加载扩展。

## v0.3.39 豆包侧栏入口与最近会话区分

页面同时出现侧栏“新对话”和同名最近会话时，优先选择侧栏上方的操作入口，不把历史会话标题当作新对话按钮。更新后重新加载扩展并刷新豆包页面。

## v0.3.38 豆包侧栏新对话入口定位

豆包侧栏未使用标准导航标签时，通过左侧可见“新对话”文字定位并点击入口，避免工具栏重复控件造成歧义；仍不能唯一定位时停止发送。更新后重新加载扩展并刷新豆包页面。

## v0.3.37 豆包新对话入口识别修复

豆包“新对话”按钮带快捷键提示或页面同时显示多个新对话入口时，优先选择侧栏中明确标注的入口，避免把同一动作的图标和文本重复计算。仍有歧义时会停止发送。回复仍按任务编号及发送后绑定的对话读取，不会采纳其他任务或旧对话的回复。更新后在 `chrome://extensions` 重新加载扩展，并刷新豆包页面。

## v0.3.36 豆包后台唤醒与回复检查

发送前自动激活未选中的豆包标签页，网页操作完成后恢复先前标签。等待回复时每隔一段时间短暂唤醒豆包页并重新检查已完成内容，避免后台页面暂停 DOM 更新导致回复滞留；读取和恢复只检查原对话，不重复发送。更新后在 `chrome://extensions` 重新加载扩展。

## v0.3.35 自动唤醒被冻结的网页标签

Chrome 冻结长时间未使用的后台网页时，标签内脚本无法响应扩展消息。本版在网页操作前检测冻结状态，必要时短暂激活绑定标签唤醒网页，操作完成后恢复用户之前查看的标签；用户在此期间主动切换时不会强制切回。更新后在 `chrome://extensions` 重新加载扩展。

## v0.3.34 LLM 任务界面优化

扩展侧栏增加当前任务状态与阶段进度卡片，并统一优化连接、输入和结果区域的层级与交互反馈。项目网页右下角任务中心在收起时显示当前任务、进度及执行中、排队、待应用和异常数量；展开后显示任务卡片和操作入口。更新后在 `chrome://extensions` 重新加载扩展，并关闭后重新打开侧边栏。

## v0.3.33 对话入口去重与任务对话绑定

豆包新对话入口按可点击控件去重，避免一个按钮被页面内层节点重复计数。任务发送成功后保存对应对话 URL / ID；恢复和读取前先校验当前对话，切换到其他会话时暂停读取，回到原对话后自动继续。

更新后在 `chrome://extensions` 重新加载扩展，并刷新豆包页面。旧任务没有对话 ID 时仅在本次请求仍能在活动对话中核对的情况下补绑，不会依据标签页本身猜测会话。

## v0.3.30 JSON 语法自动修复

收到带完整任务标记但 JSON 语法无效的回复后，扩展保留原文，在当前对话请求一次仅修正语法的完整回复。修复使用独立标记并继续校验原任务编号，避免误读旧回复；不会覆盖已有草稿，不会无限重试，也不会重置任务的 300 秒期限。结构缺字段或任务编号错误不会触发语法修复。已结束的错误任务需要重新发起。

更新后重新加载扩展并刷新 LLM 网页，以加载新的网页脚本。

## v0.3.29 豆包文字网页接入

增加豆包网页文字发送与回复读取。项目任务会优先使用已打开并登录的豆包标签页；每次新对话策略下，发送前会在当前标签页点击“新对话”并确认页面已清空。当前仅支持文字，不上传视频、图片或其他文件。更新后在 `chrome://extensions` 重新加载扩展，并刷新豆包页面；页面结构与控件可能变化，首次使用需确认已登录且输入框可用。

## v0.3.27 DeepSeek 继续生成按钮

DeepSeek 的“继续生成”命中时，优先点击真正的 `button` / `[role=button]` 容器，而不是其中的文字 `span`；诊断日志分别记录激活控件与指针命中元素。更新后在 `chrome://extensions` 重新加载扩展，并刷新 DeepSeek 页面。

## v0.3.28 DeepSeek 真实鼠标输入

如果 DeepSeek 忽略网页脚本触发的合成点击，扩展会在确认任务、网站、标签页及按钮坐标后，用 Chrome debugger 鼠标输入协议激活续写按钮，并立即断开 debugger。安装时需接受新增的 debugger 权限；不能附加时会记录失败原因，不会继续发送原始请求。

## v0.3.26 后台保持绑定网页

项目提交或恢复发送任务时，扩展保持 ChatGPT / DeepSeek 标签页在后台运行，不切换前台标签。绑定的服务标签页会设为不可自动丢弃；如果此前已被 Chrome 丢弃，扩展会在后台重新加载后继续操作。更新后，在 Chrome 扩展管理页重新加载扩展。

## v0.3.25 后台标签页主动读取

后台任务轮询现在会主动重新检查绑定网页中的回复内容，同时保留 DOM 变化监听作为即时路径；避免后台标签页没有触发可见 DOM 变化时，必须手动切换标签页才能取回已经完成的回复。更新后，在 Chrome 扩展管理页重新加载本扩展，并刷新 DeepSeek / ChatGPT 标签页。

## v0.3.24 编辑器提示词隔离

项目勾选「使用编辑器提示词」时，扩展强制开启新网页对话，避免同一分段旧对话中的完整提示词影响本次修正；全屏编辑页同时显示实际选中的提交提示词供核对。更新后，在 Chrome 扩展管理页重新加载本扩展，并刷新 DeepSeek / ChatGPT 标签页。

## v0.3.23 继续生成点击路径

续写优先调用实际命中元素的原生 `click()`，第二次无增长重试使用完整指针事件序列（click 也使用 PointerEvent）。点击前立即滚动到可视区域并检查中心命中元素，支持文字层不接收鼠标事件的按钮，拒绝点击遮挡层。诊断记录包含实际目标及 native-click / pointer-sequence；发出事件仍不等于续写成功，继续以回复增长验证。保留最多三次尝试及总超时限制。

## 从 v0.1 升级及配对

v0.2.2 在 DeepSeek 无法通过语义标签识别发送图标时尝试输入框 Enter 提交，并检查输入框是否清空。若未清空，会停留在待确认状态，避免误报已发送或重复提交。读取回复时也会检查请求是否仍未发送。此适配已通过模拟页面测试，仍需在实际登录页面验证。升级时先处理当前已填入的请求，再重新加载扩展并刷新 LLM 标签页，让新版网页脚本生效。

1. 重启项目后，在 `chrome://extensions` 对本扩展点击「重新加载」，刷新已打开的 LLM 标签页。v0.2 新增本机后台访问和 alarms 权限。
2. 项目「设置 → 模型配置 → 网页 LLM / Chrome 扩展」中展开「连接 Chrome 扩展」，复制后台地址和配对码。
3. 扩展侧边栏「连接项目后台」填写地址和配对码，项目任务按服务自动绑定已打开的 DeepSeek / ChatGPT / 豆包标签页，然后点击「保存并启用连接」。只有明确绑定的标签页可被后台任务使用。
4. 启用后台连接后，无论侧边栏打开还是关闭，都按 1 秒间隔检查任务。关闭侧边栏时由 offscreen 页面中的 Worker 驱动；30 秒 alarm 仅用于异常恢复。检查尚未完成时不会并发叠加。浏览器休眠、系统休眠或请求耗时可能导致延迟；关闭浏览器后不会工作。v0.3.10 新增 offscreen 权限，更新后须重新加载扩展。
5. 选择不同服务时，各服务需有对应的已登录并绑定标签页。后台会排队等待可用服务，不会擅自改用其他服务。

## 项目里的统一选择

- 全局默认：DeepSeek / ChatGPT / 豆包网页服务。
- 功能覆盖：剧情、Beats / 小说拆分、分段提示词、问题分析、视频反馈修正及其他通过共享 LLM 客户端的调用，可分别配置。
- 为保持原有行为，既有生成入口初始显式选择 DeepSeek API；切换为「跟随全局」后使用全局网页服务。已有 API 配置仍然有效。
- 视频反馈修正还可选择本次服务，优先级为「本次任务 > 功能覆盖 > 全局默认」。本次任务提交后不会随全局配置变化而改投其他服务。
- 千问仍在服务目录预留并禁用；豆包现已支持网页文字收发。
- 全屏编辑器：左侧参考素材，中间提示词，右侧最新成片和问题反馈。修正只生成候选稿；「应用到编辑器」不自动保存，「应用并生成」则保存并调用既有视频工作流。
- 成片优先使用生成历史对应的提示词快照。旧视频缺少快照时，必须手动提供当时使用的提示词。项目、视频、参考配置或编辑稿变化时拒绝覆盖，需手动合并。

## 安装

1. Chrome 地址栏输入 `chrome://extensions`。
2. 打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」。
4. 选择本目录（必须直接包含 `manifest.json`）：

   `F:\work\comfyui\ai_cartoon_factory\tools\chrome_prompt_bridge`

5. 在 Chrome 工具栏的扩展菜单中找到「视频提示词修正助手」，固定到工具栏。点击图标打开侧边栏。
6. 打开并登录 `https://chatgpt.com/` 或 `https://chat.deepseek.com/`，刷新扩展的标签页列表。

更新扩展文件后，在扩展管理页点击本扩展的「重新加载」，并刷新目标 LLM 页面，避免旧版本内容脚本继续运行。

## 使用

1. 建议新建一个专门修正提示词的网页对话，然后在侧边栏选择该标签页。
2. 粘贴实际生成视频时使用的完整提示词，填写问题。可补充时间点、期望效果、素材编号和时长。
3. 「仅填入网页」可先检查内容；也可以点「提交并等待修正」自动填入并点击发送。
4. 扩展自动识别发送按钮并提交；豆包优先识别发送按钮标记，并在必要时定位输入框右下角的提交控件。自动发送未确认时会继续检查，不会把任务提示成需要手动发送，也不会盲目重复提交。
5. 完整回复带有本次任务标记，且停止变化至少 4 秒后，扩展显示修改说明和完整修正版。点击「复制修正版」或「导出记录」。
6. 要发起下一次修改，先等本次完成，或「结束本次等待」。结束等待不停止网页模型自身的生成。

发送之后不会自动再次点击发送。关闭侧边栏不会停止当前页面里的读取；刷新网页后，后台任务会按原任务编号恢复检查。项目后台任务的 900 秒期限从扩展领取开始，排队时间不计入；超时后迟到回复仅保留记录，不自动应用。

## 网页适配

- ChatGPT 默认输入框：`#prompt-textarea`；回答：`[data-message-author-role="assistant"]`。
- DeepSeek 默认输入框：`textarea[placeholder]`；回答：`.ds-markdown`。
- 豆包默认尝试 `textarea[placeholder]` / `textarea` / 可编辑区域识别输入框；只收发文字，网页更新后可在网页适配设置中配置选择器。
- 发送按钮优先识别 `data-testid="send-button"` 和明确的发送文字/无障碍标签。豆包还会识别无标签发送箭头，并在找不到按钮时自动尝试 Enter 提交。
- 「网页适配设置」支持对两个网站分别覆盖输入框、发送按钮和回答正文 CSS 选择器。发送与输入框必须唯一匹配；回答选择器必须只包含模型回答，不能选整页或包含用户请求。
- 默认选择器属于兼容性适配，不保证所有账号、语言和网页改版均可用。首版做了本地协议与交互模拟测试，尚未在用户实际登录对话中完成发送联调。
- 仅文字反馈，不读取、上传视频，不声称模型已看过成片。登录失效、验证码、额度不足需要在网页处理。

## 本地数据和权限

- 权限涉及两个 LLM 网站、本机 HTTP 后台（127.0.0.1 / localhost）、脚本注入、侧边栏、定时检查和本机扩展存储。没有 Cookie、所有网站、远程调试或本地文件权限。
- 不读取登录 Cookie，直接复用标签页已有登录会话。
- 独立任务由用户点击触发；启用后台连接后，项目任务自动发送到明确绑定的标签页，不会使用其他标签页。
- 草稿、网站适配设置、当前任务和最近 10 次任务保存在 `chrome.storage.local`，不使用 Chrome 同步。历史记录暂无列表界面，完成结果可导出 JSON。
- 手工侧边栏一次处理一个任务；项目后台任务可跨服务并行，同一服务一次一个任务。当前任务等待时不覆盖原文；网页输入框已有其他草稿时拒绝覆盖。
- 模型回复通过 JSON 解析并以纯文本展示，不作为 HTML 或脚本执行。
- 后台队列和配对码保存在 `%LOCALAPPDATA%/AICartoonFactory/web_llm_bridge/<安装目录标识>/bridge.sqlite3`，不放在项目可下载的媒体目录中。
- 回传校验配对码及单次领取凭据，重复回传幂等。已取消、超时的任务不会自动应用迟到结果，也不会自动重新发送。项目后台任务从扩展领取时计算 900 秒网页执行期限。
- 草稿及结果属于本机数据；扩展传给网页 LLM 的内容为任务中的提示词、反馈和上下文，不上传视频、参考图或浏览器登录凭证。

## v0.3.0 自动新对话

扩展「对话策略」统一控制项目任务和手动提交，可对剧情、Beats、分段提示词、问题分析、反馈修正及其他调用分别覆盖。

- 每次新对话（默认）：在绑定标签页中开启新对话，再填入本次完整请求。不新增标签页，不删除旧聊天。
- 智能复用：同一项目、同一视频段的连续修正可复用；独立任务或更换对话页面自动新开。默认上限 5 轮、30000 字符，任一达到后下次新开。字符统计是扩展已发送请求及已读取回复的长度，不是模型 token，也不包含用户自行加入的内容。
- 始终复用：保留当前对话。

设置保存后只影响新任务。读取、回传、当前任务重试不新开；上一任务未结束或结果未回传时阻止下一任务。输入框有草稿时不切换。无法识别新对话按钮或无法确认切换时停止提交并显示错误，不悄悄发送到旧对话。

升级：更新加载目录，在 Chrome 扩展管理页重新加载，刷新 DeepSeek / ChatGPT 页面并重开侧边栏。项目后端重启后，新建反馈任务才带同段修正的复用标识；旧后台任务没有标识时按独立任务处理。实际网站可能改动按钮标签，需要实际登录页面验证。

## v0.3.2 自动恢复提交

后台轮询现在执行恢复流程，而不只是读取：先找当前请求编号；若未发送，则自动继续填入和发送。新对话切换导致脚本中断时，下次轮询会继续同一个任务。旧版本由读取误写的 sent_at 在空白新对话中会自动迁移。

发送尝试有独立的持久化记录。请求原文仍完整留在同一页面输入框、且没有本次请求记录时，间隔至少 10 秒自动重试，最多 3 次。输入框清空但找不到编号属于结果不明确，停止自动重发并报告错误，避免重复生成。其他草稿不会覆盖，已找到回复的任务只读取回传。

更新加载目录后重新加载扩展并刷新 LLM 标签页一次。之后项目任务不需要复制、粘贴、手动发送或点击读取。超时或已取消任务不会自动重新创建。本版恢复流程通过模拟测试，实际已登录网站仍需验证。

## v0.3.3 新对话文字入口

新对话识别增加可见 div/span 中的精确入口文字，支持没有 button 角色的按钮结构。嵌套父子节点去重后点击文字节点，事件冒泡到实际控件；识别歧义时自动暂缓重试。新增嵌套结构到自动填入发送的模拟回归测试。更新后重新加载扩展并刷新 LLM 页面。

## v0.3.4 ChatGPT 自动发送

ChatGPT 在无法识别语义发送按钮时也支持 Enter 提交，扩展发送标签匹配，填入后等待编辑器状态和发送按钮就绪。继续使用编号检查和有限恢复机制。新增 ChatGPT 无标签发送控件的模拟回归测试；实际网页仍需验证。

## v0.3.5 ChatGPT 输入框识别

后台实测任务报“无法唯一识别输入框”。新增 role=textbox、Lexical、ProseMirror 和表单内编辑器的候选识别，优先使用现有明确 ID；排除不可编辑或禁用节点，多个候选时不填入。自定义选择器仍以用户配置为准。新增无旧 ID 和多输入框回归测试，实际用户页面 DOM 尚未直接验证。

## v0.3.6 排除草稿中的任务编号

判断请求是否已发送时，移除页面副本中的输入框、contenteditable、script/style，再查找本次编号。富文本编辑器的段落空白差异不再把本次草稿误判为其他草稿。恢复已经填入的同一请求不再次开启新对话。新增草稿包含编号、段落换行变化的回归测试。需重新加载扩展并刷新网页使修复生效。
