# H3 人物状态自动维护

用户沿用现有场景选择、优化、应用、保存、生成操作，状态补录与依赖核对在内部完成，不新增必点确认步骤。

## 自动准备

continuity/preparation.py 的 ensure_scene_state 按明确的 scene_context_id 准备当前操作所需前链，include_target=True 时也准备当前固定稿。它仅修改传入快照的状态元数据。prepare_runtime_state 在锁外执行模型请求，再在短锁内核对来源并保存。

打开页面和普通保存不隐式调用模型。优化前自动准备上游；生成、批量生成、已有工作流提交及重试自动准备上游和当前段。已有稿计划缓存 shots=[] 不代表本段无状态变化，缺记录时解析真实提示词 Shot 并提取，不重新构图。

场景归属、顺序、初态或选用视频变化后，下次现有优化/生成操作自动核对受影响记录。相同稿件与输入复用记录，不反复调用模型。场景归属继续以明确选择为准，不按背景图自动合并。

## 固定稿提取

state_trace.extract_state_record 独立调用提示词路由，返回逐镜位置、姿势、在场事件和开场要求。角色使用稳定 role_id，事件及要求必须引用所属 Shot 原文。模型不能返回新提示词、构图、visible_roles、台词、素材或时长。

程序校验字段、类型、角色、Shot UID、原文依据，用 reducer 计算末态。validate_state_result 提供同一严格校验用于明确标记为 reviewed_recovery 的结构化恢复资料，不冒充服务调用。

前驱事实相同、仅来源变化时可本地重绑；事实变化则重新核对固定稿开场。能够 replay 事件不代表镜头兼容。无关未知保留未知并继续，关键开场依赖无法核对才暂停。未入画不代表离场，不强制全员同框。

## 版本与保存

versions.py 读取精确选用的成功 render，不隐式改选。上游有选用视频时使用其提交稿、参考绑定及关联状态；否则使用已保存稿。批量目标在内存中明确采用本批新稿。当前目标提交前始终核对自己的当前稿。

历史 render 快照不修改。旧视频的派生记录存入 h3_continuity_versions[render_id]，稿件版本相同时才同步顶层记录。切换选用后自动读取对应版本，未提交的新草稿不替换选用视频的承接来源。

构图候选始终携带上游来源签名。保存时在现有锁与两文件事务内验证来源，原子保存稿件、参考绑定和状态。异步期间来源变化不能被旧结果覆盖。纯状态维护保留视频与工作流状态。

## 视频提交

H3 编译和提取在锁外，平台接受任务仍串行。准备结果经 CAS 合并，提交锁内再次核对来源；已有接受任务优先保护，重复点击不重复提交。

工作流按内容哈希独立保存并原子发布，不覆盖历史文件。场景段已有工作流缺少或不匹配稿件版本时，以当前固定稿重建，再核对状态。

## 构图与反馈

“根据人物状态优化提示词”保留主动构图语义。原镜头适合时优先保留，不为登记状态增加静默旁观者。受保护的局部补丁保留动作、对白、声音和时间。应用只改浏览器稿，保存才落盘。

普通缺失、过期记录将在当前操作中自动整理，不引导回头重做视频。真实冲突报告具体 Part、Shot、人物、字段和原文。失败或取消结束忙碌状态，保留原稿和选用视频。

状态是稿件计划事实，不能宣称已识别视频。生成成功不代表画面已经验证；实际画面差异由明确的人工校准提供，不由运行时代码猜测。
