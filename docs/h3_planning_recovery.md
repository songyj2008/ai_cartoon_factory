# H3 分镜对白修正与任务草稿恢复

Beat 到 Segment 的规划请求提供本段台词序号表 `dialogue_catalog`。模型在各 Shot 的 `dialogue_refs` 中分配完整台词序号，程序按明确分配带入原文、说话人和声音归属，避免模型重复抄写造成漏句或改写。序号须按顺序覆盖全部台词且各出现一次；程序不猜测遗漏台词的位置，不自动补剧情。最终提示词仍经过对白一致性校验。编辑稿重规划继续以编辑稿为唯一底稿。

分镜规划继续逐字校验对白、顺序、说话人和声音归属。允许一句对白按原文连续拆到多个镜头；不因切镜重复整句。原稿明确写了多次的对白按原次数保留。

普通 Beat → Segment 使用可编辑草稿规划：模型按完整对白自然估时，输入秒数仅供参考；超过 15 秒仍保存，显示提交范围提示。对白缺失、重复、归属、序号或结构问题随原始回复一起保存，不自动修正重发，也不阻止下一 Beat。无法解析的回复保留为待重试草稿，重试失败时保留原有可编辑结果。

旧的严格规划接口仍保留用于独立校验；该接口对白校验未通过时，规划器把当前底稿、错误分镜、期望对白及各 Shot 的实际对白交回模型，最多修正一次。修正请求使用独立且稳定的 `h3_prompt_plan_NNN_repair1` 阶段编号，避免重新读取第一次的错误结果。修正后仍检查全部镜头时间、时长和对白约束。网络中断、网页任务状态不明和 `needs_replan` 不触发对白修正重发。

已通过校验的分镜计划保存到当前文字任务工作目录的 `temp/h3_planning_checkpoint.json`。缓存仅存在于隔离的任务草稿。

小说入口现在创建可续跑批次：总批次只汇总状态，Beats 是一个独立任务，每个 Beat 对应的 Segment 是一个独立任务。Beats 校验通过后立即应用到原项目并刷新页面，然后按顺序创建分段任务。每段通过后只合并该段，立即显示已保存的分段；后段仅承接前段可靠的结束状态；前段有问题时按自身 Beat 规划，不沿用错误分镜。

“参考 Beat 数量”仅供 LLM 参考，可按完整对白、事件边界和单段时长适当增减。本地不要求实际数量等于参考值，不裁剪、复制或补齐 Beat。仍校验模型允许的单段时长和目标总时长，后续按实际 Beats 数量创建 Segment 任务。

再次提交相同小说、时长、分段数、模型、项目设定、素材和路由时，恢复原批次，保留已保存的 Beats 和 Segment，仅重试失败或未完成步骤。修改已完成 Beat 或单段重试时，仅重做目标段，保留后段并标记承接信息需检查。发布前核对 Beat 和前段结束状态，冲突时保留候选。网页请求状态不明时仍需检查原请求，不自动重发。

页面通过现有事件流和刷新机制更新。分段完成只刷新分段区域，不替换剧情或 Beats 编辑器；存在未保存的分段编辑时暂停自动刷新。总批次展示已完成数，子任务可单独查看；失败后可点“继续未完成分段”或对应步骤的重试。批次及其子任务不随普通短期历史过期，手动清空任务记录会移除对应恢复记录；清空已结束任务不会删除仍被运行批次引用的成功步骤。

独立提示词任务失败后重新提交时，只有原文、参数、编辑稿、项目快照、元数据和路由配置均一致，才继承失败任务的缓存。每段仍按完整规划输入指纹匹配并重新校验；网页领取凭据、未完成请求和失败答案不随草稿继承。

更新后重启项目后台并刷新页面即可生效，无需更新 Chrome 扩展。旧版失败小说任务若保留已完成的 Beats 草稿，且输入和快照仍一致，会直接恢复该 Beats 阶段；没有保存的分镜计划无法恢复。

分镜草稿保存与视频工作流构建分开：规划阶段不构建可提交工作流，实际提交时按现有 H3 4–15 秒整数、有效时间线和参考素材契约重新校验并构建。对白内容问题仅提示。Shot 编辑、重新规划时长可保存超限草稿，页面显示预计总时长及各段具体问题。各段提供“重新生成 Segment”，包括失败或没有有效分镜的 Beat。
