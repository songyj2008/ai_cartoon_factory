# 分段视频生成渠道

“分段模型”和“生成渠道”是两个独立选择。分段原有的 LTX/H3 模型、时长和素材不会因选择渠道而被改写。在分段卡片点击“重新生成”后，先选择 ComfyUI、RunningHub、豆包网页版或 RunningHub 网页版（H3）；不满足当前渠道条件的选项显示原因。

## 豆包网页版

- 使用已有 Chrome 扩展的本机配对配置。更新代码后重启项目，并在 `chrome://extensions` 重新加载 `tools/chrome_prompt_bridge` 扩展。扩展使用一个专门的豆包标签页自动完成网页操作。
- 免费账号渠道接受 **4–10 秒整数时长**、非空视频提示词和至少一张本地参考图片。目标比例固定为 **16:9**。当前只传图片，不传 H3 的视频或音频素材；这类分段会显示不可用原因。
- 在网页自动点击“视频生成”、设置比例与时长、通过左下角加号上传参考图、填写提示词并发送。扩展继续检查新视频与下载状态，将下载文件写入分段渲染记录。不会自动重发发送状态不明的任务。
- 默认账号每天最多预留 10 次，额度在本机队列中跨项目计算。可在 `config.json` 的 `web_video_accounts` 中为渠道设置稳定的账号标识；默认标识为 `default`。发送前明确失败的任务不占额度；已发送或结果不确定的任务占额度。
- 队列数据库位于用户的 `LOCALAPPDATA/AICartoonFactory/web_video_bridge`。同一项目安装位置使用同一个数据库；系统本地日期决定每日额度。

网页 DOM 会随豆包更新。扩展在比例、时长、上传预览或发送确认无法验证时停止任务并记录错误/不确定状态，不会盲目点击或自动改用其他渠道。首次使用和网站改版后，应在已登录的豆包页面用一个 4–10 秒分段做端到端联调，特别检查预览上传和结果下载控件。

## RunningHub 网页版（H3 / Runow）

- 独立渠道 ID 为 `runninghub_web`；现有 `runninghub` 仍提交云端 ComfyUI 工作流。Runow 的素材、提示词和页面逻辑分别放在 `services/runow_web.py`、`generation/channels/runninghub_web.py`、`tools/chrome_prompt_bridge/video/runow.js`，不经过豆包适配器。
- 仅接受 H3 多模态参考分段、4–15 秒整数时长；图片最多 9 张、视频最多 3 个、音频最多 3 个。至少包含图片或视频。文件名在本次任务内必须唯一；不会自动丢素材、改时长或改剧情。视频内嵌音轨作为独立 `<Audio n>` 引用尚不支持，应提供单独音频文件。
- 从分段读取比例（默认 `16:9`）；`generation_config.runow_resolution` 可设置 `480p`、`768p`、`1080p`，默认 `1080p`。参数以网页实际支持为准，无法回读一致设置时停止，不降级参数。
- 0.4.62 在项目内创作表单提交时补齐多素材参数。网站首页和项目底部快捷创作共用的参数映射会只保留首图，切换页面入口仍会触发该问题。扩展按任务文件名收集素材库接口返回的原始地址，在本任务的 prepare、commit 请求中依次写入 refImage1–9、refVideo1–3、refAudio1–3，并在结束后恢复页面请求方法。流程为“新建空项目 → 继续创作 → 视频 → Minimax H3-RH增强版”。在项目面板的图片、视频、音频入口分别点击“从资源选择 → 我的素材”。优先比对完整文件名，未找到才搜索；唯一同名、同类型素材直接复用。每类素材按参考顺序选择，点击页脚“添加已选”，确认弹窗关闭和类型内引用编号后，再填写提示词并通过项目内按钮生成。网站明确显示搜索无结果时，用该弹窗的“本地上传”将本次任务文件上传入库。后续网站修复多素材映射后，再重新评估并移除该请求补丁。

## 扩展新的渠道

1. 在 `generation/channels/` 新增渠道模块，导出 `channel`，实现 `id`、`label`、`uses_workflow`、`unavailable_reason(segment, payload)`、`submit(service, segment_index, wait=...)`。网页渠道还可复用 `services/web_video_bridge.py`，实现 `assets(segment)`、`duration(segment)`、`prompt(segment)`；按需定义 `daily_limit`。
2. 将模块路径加入 `generation/channels/registry.json`。打包脚本会收集渠道子模块和注册表。
3. 网页渠道在 `tools/chrome_prompt_bridge/video/` 新增单独的网页 DOM 适配器，并在 `video/channels.json` 注册渠道 ID、页面 URL、域名和脚本路径。Chrome 扩展 `manifest.json` 的 host permissions 需包含新网站。
4. 渠道适配器必须验证网页操作后的可观察状态，再回报提交或完成。核心分段服务、原有工作流模板和其他渠道不需要加入网站分支。

多模态渠道可选实现 `build_request(segment)`、`public_input(request)` 和 `resolve_asset(request, asset_id)`，共享队列只调用这三个扩展点；旧图片渠道仍使用原接口。扩展可在 `VideoChannelDrivers` 注册自己的载荷准备、URL 范围、原生文件选择及标签页生命周期能力。
