# H3 台词节奏统计与时长规划改造方案

日期：2026-10-15  
状态：核心数据链路、跨项目人物检索及两个规划入口已实施，已完成回归测试与现有库回填；新规划和成片效果待实际使用核对。现有分段及视频未自动重生成。

## 1. 目标与责任边界

把用户人工核对通过的视频 OK 样本转成可计算、可追溯的逐句节奏数据。没有个人样本的人物先使用参考音频和库级中位数；人物积累自己的 OK 样本后，优先参考自身节奏。LLM 根据当前台词、情绪和发声方式规划时间，本地代码计算统计并校验结构。

不设置固定字数上限、情绪倍率或故事专用秒数，不围绕某个角色、会议场景或一次生成失败新增运行规则。统计数值是规划依据，不是强制播放速度。

范围是现有 H3 的时长估计和经验库，不改生成工作流，不增加旧流水线兼容。

## 2. 统一估时规则

| Shot 类型 | 时间预算 |
| --- | --- |
| 有言语 | 以原台词自然说完所需时间为主，包含必要重音、换气和短停顿。画内对白、画外音、电话、旁白和跨镜续说都属于言语。 |
| 无言语 | 按必要动作、表情变化、事件发展及明确叙事节拍估时。音乐、环境音和音效不算台词。 |

辅助表情、姿势、眼神、手势和镜头变化在发声期间完成，不逐项加时。只有原剧情明确要求先后发生、无法与发声并行的必要事件单独占时。多人顺序接话按顺序计时；明确重叠的发声按其覆盖区间计时。同一句跨镜续说只计算一次。

先逐镜估计，再汇总为分段时长；最终才按 H3 合同确定允许范围内的整数总长，不逐镜向上取整。仅重新规划时长时保留原稿内容和现有时间标记，不补写剧情或额外对白窗口。

## 3. 统计定义

### 3.1 语速口径

逐句计划语速 = 对应台词汉字数 / 对白窗口秒数。

- 标点不计入汉字数；对白窗口包含正常换气和句间短停顿。
- 当前先明确支持中文汉字统计。数字、英文及混合语言须标识计数口径；无法确定口语读法时不猜读音或混入纯汉字基准。
- 仅有整个 Shot 时间、且含独立准备动作或多位说话人时，不能直接当作某一句的对白窗口。
- 台词文字列在多段时间说明之后时，按显式发声声明选择窗口，不能把“说完闭口”等收尾静默窗口算作对白。多区间存在歧义时暂不计算，不按语速数值快慢判断资格。
- 对白窗口与原句明确，但未能绑定素材人物的临时角色，可参与库级统计，暂不参与任何个人统计，单独报告未归属数量。
- 同一句跨 Shot 续说，按原句完整文字及其完整发声覆盖时间计一次，不能每镜重新计算整句。
- 多人重叠对白各自计算个人语速；汇总片段时按时间区间关系处理，不能把重叠窗口简单相加作为视频总长。
- 不将成片总时长按比例摊给各句，也不以台词字数除以包含大量无言语内容的整段时长。

### 3.2 基准与分组

- 库级基准：同模型、同语言、同计数与时间口径的合格逐句语速的中位数。统计全量启用数据，不是检索给 LLM 的少量样本。
- 人物基准：同一素材库人物稳定身份下的合格逐句语速中位数，跨项目、跨角色名称汇总。项目名、角色名和项目内角色编号不参与人物身份分组。
- 音色版本是同一人物样本内的来源及检索维度，不因更换录音创建另一个人物。同音色的相近样本可优先参考，同时保留人物跨音色版本的总体统计。
- 同时提供句数、成片数、语速分布与来源；数据足够时补充四分位区间。
- 个人数据很少时同时提供个人值和库级值，不让一条特殊情绪样本被误解为人物固定语速。
- 情绪和发声方式作为样本描述保留。样本积累后可增加相近表达的分组统计，不预先硬编码情绪类别及倍率。
- 15 字/秒等人工认可数据保留，不因数值快而自动剔除；通过情绪、表达方式和分布信息说明其适用性。

### 3.3 前述两份样本的算例

8 句语速按完整精度计算、排序并取中位数，展示时再舍入：

`4.55、5.37、6.00、6.00、6.36、7.84、8.57、15.00 字/秒`

- 两份样本的库级算例中位数约为 **6.18 字/秒**；实际库级值应扫描全部合格样本计算。
- 陈默两句的个人中位数约为 **6.61 字/秒**。
- 赵鹏一句的个人中位数为 **6.00 字/秒**，需要同时标明只有一条数据及原表达方式。
- 之前讨论中的 7.27 字/秒是两份样本的加权平均值，6.44 字/秒是陈默的加权平均值，均不等同于中位数。

这些数字是当前数据的计算结果，不作为代码默认常量。

### 3.4 同一人物跨项目、跨名称归并

项目中的角色身份与素材库中的人物身份分开：同一个素材人物可以在不同项目扮演不同角色，所有合格节奏样本仍归入同一个人物池。

身份链路采用 `project_role.asset_identity_id → manifest.metadata.identity_id → canonical_identity_id`。已有素材库 id 可直接作为稳定身份；若同一人物被重复导入成多个素材 id，使用明确的人物归并映射指向统一 id，保留旧 id 的来源记录，不依赖姓名、图片文件名或 LLM 猜测。

- 名称只是样本当时的展示标签：角色改名不丢失历史样本，不产生新人物池。
- 同名但绑定不同素材人物的角色不合并；不同名但绑定同一素材人物的角色必须合并。
- 项目内的 `character_001` 和请求内的 Subject/Audio 编号可能重复，不能作为跨项目人物键。
- 不仅统计要跨项目，提交给 LLM 的人物参考检索也须跨项目。当前 `retrieve()` 的同项目过滤需要调整：先按统一人物身份找全库自身样本，再按音色、表达方式筛选参考；项目只记录来源，不阻断自身样本复用。
- 全库人物经验可复用节奏和表达依据；当前项目角色名、剧情和台词仍完全以当前输入为准，不从历史项目恢复旧剧情。
- 同音频指纹用于音色匹配，不单独证明两个素材人物是同一个人。

## 4. 样本入库与生命周期

### 4.1 OK 的业务含义

本流程将用户标记 OK 视为：人工已核对该成片的台词完整度及节奏分配可用。保留 `reviewed_by=human`、台词完整度和节奏认可状态。LLM 不声称自己听过音轨。

对历史记录，按本次用户确认的适用范围回填人工认可状态；缺少信息的其他记录不伪造审核结论。人工认可的计划窗口与精确音轨测量采用不同来源标签，但前者正常参与已认可分配的统计。

### 4.2 数据来源

使用标记时所选成片版本的 `prompt_snapshot`、`asset_manifest`、音色指纹和 Render 标识，不使用当前编辑稿或人物库后来替换的音频冒充历史输入。

优先从已有结构化分镜或可明确解析的提示词中取得对白窗口。自然语言格式无法直接提取时，可让经验分析 LLM 提取候选结构；本地核对原句、说话人、引用位置和时间边界后，才纳入统计。不能可靠提取的行记录原因，暂作为定性经验或镜头预算参考，不编造窗口。

### 4.3 逐句记录建议

| 字段 | 用途 |
| --- | --- |
| `sample_id`、`render_id`、`line_id` | 追溯到成片版本与原句 |
| `model_id`、`language`、`counting_basis` | 确定统计分组 |
| `canonical_identity_id`、原 `identity_id`、`voice_fingerprint` | 跨项目统一人物身份、原素材来源及音色版本 |
| `project`、`role_id`、`role_name_at_generation` | 追溯当时扮演的角色，不作为人物分组键 |
| `dialogue_text`、`hanzi_count` | 原句及本地计数 |
| `speech_intervals`、`speech_window_sec` | 原句覆盖的窗口及总时间 |
| `chars_per_sec` | 本地计算值，不采用 LLM 自报结果 |
| `scope`、`delivery` | 发声用途和原稿情绪语气 |
| `timing_basis`、`source_evidence` | 计划窗口或实测、原稿引用证据 |
| `human_review`、`eligibility_status` | 人工反馈与能否参与统计 |

Subject、Audio 编号只在原请求内部有意义，不能作为人物全库统计的键。

### 4.4 更新规则

1. 标记 OK：保存不可变快照，能直接提取的结构立即入库；需 LLM 提取的记录先进入待处理状态。
2. 数据通过结构校验：重新计算受影响的库级与个人统计。定性分析失败不妨碍已经可靠提取的数值样本参与统计。
3. 取消 OK：停用对应版本的数据并重新计算；重新启用恢复资格，不生成重复记录。
4. 同一成片重复点击、任务重试、归档副本不重复计入；去重保留完整来源关联。
5. 统计不足或暂不可用时向规划器明确提供数据缺失状态，不伪造默认语速。

初期建议从合格记录按需汇总，避免维护一份容易过期的中位数配置；数据量增长后再缓存，并在样本变更时失效。

## 5. 没有个人 OK 样本时的参考音频

已有 `services/character_voice.py` 保存参考录音的 `transcript` 和 `duration_sec`，可以复用。

- 原文与录音对应时，计算参考录音的汉字数、对应时间及语速。
- 可去除首尾额外空白，保留正常发声过程中的换气和停顿，使其与 OK 对白窗口的计时口径可比较。
- 尚未分析首尾空白时，保留 `duration_basis=file_duration`，明确文件时长可能包含额外空白，不冒充处理后的说话区间。
- 原文缺失、不对应或录音含无关片段时不强行推算；可使用库级中位数起步。补录或音频识别属于单独的数据补全步骤，不能静默猜测原文。
- 记录原录音的表达方式及信息完整度。音色参考的情绪、语速不是当前人物必须照搬的表演指令。

同时提供参考录音语速和库级中位数，交给 LLM 判断当前表达更接近哪种依据；不硬编码两者各占一半等权重。人物有少量自身样本时也保留这些补充依据，随着个人样本积累提高其参考优先级。

## 6. 交给 LLM 的数据与任务

### 6.1 输入结构

在现有输入中增加 `speech_timing_context`，包含：

- `population`：模型、语言、计数口径、库级中位数、有效句数、成片数和分布。
- `speakers`：逐人物稳定 id、当前音色指纹、个人统计、参考录音数据、可用依据来源及缺失项。
- `examples`：少量相近人物/音色/表达方式的逐句节奏样本及人工认可状态，不发送整库历史剧情。
- `statistics_version`：本次统计快照，便于复现规划理由。

当前完整提示词或 Beat 仍是剧情和台词事实源。统计只负责提供时间依据，不能从旧样本补入人物、对白、镜头或事件。

### 6.2 LLM 使用规则

1. 优先参考自身同音色的 OK 数据；样本少时同时参考库级统计。没有个人数据时，结合可靠参考录音和库级中位数。
2. 按当前台词字数和参考节奏形成初步时间，再结合当前语气、情绪、句子结构、发声用途调整，不使用固定情绪倍率。
3. 样本窗口已经包含必要停顿，不因“沉稳”“严肃”及同一处标点再重复追加时间。
4. 若估时明显偏离适用样本，说明具体的表达差异或不可并行事件；不能只写“略紧”。
5. 画外音、电话及旁白不要求画面中的听者开口；原有可见性、人物、音色和对白归属保持不变。
6. 只重规划时间时继续仅返回原有时间标记、分段总长与理由。输入扩充不要求变更现有结果 JSON 合同。

`duration_reason` 应能看出每个 Shot 使用的主要依据、分配时间，以及独立事件额外时间。它是简短的可核对依据，不要求输出内部思考过程。

## 8. Shot、分段、全片总长如何同步

`逐镜重新估时 → 本段汇总 → 更新对应 Beat/分段/帧数 → 重算全片计划总长`

- 同一段的 Shot 连续覆盖本段总时长；At 及其他原有时间标记同步。
- 当前只规划一段时，仅更新该段和对应 Beat，其他段保持既有值。
- Beats 的计划总长按各 Beat 求和，视频任务总长按各分段任务求和。若其他段原本不一致，本次不静默修改它们，不能承诺两个总长必然相等。
- 用户目标总时长单独保留，不通过拖长或压缩每段去强行凑目标。
- 已有成片和历史 Render 快照保持原记录；新计划应用后，后续重新生成的视频使用新时间。
- 全片重新估时需要对所有分段运行规划；本方案不擅自增加自动全片批处理入口。

## 9. 实施顺序

### 第一阶段：可靠的逐句数据与中位数

新增逐句记录和统计模块；实现标记/取消/重试的幂等性；从现有 OK 快照回填可明确提取的窗口；保留不能提取的记录及原因。展示或日志输出样本数、统计来源和中位数，先人工复核与手算一致。

### 第二阶段：人物与参考音频依据

建立跨项目统一人物身份及可选归并映射；角色名称变化继续进入同一人物池，音色版本作为样本内的检索维度。读取参考音频原文和时间来源；生成统一 `speech_timing_context`。避免只给一个整体 `voice_match=true`，改为逐人物的可用依据。

### 第三阶段：接入规划器

在重新规划和自动镜头规划入口注入相同上下文，精简重复历史长文本，统一通用规则及理由要求。新统计/提示词影响规划缓存键，新任务才能使用新输入；已经创建的旧请求保留旧快照。

### 第四阶段：回归与人工试用

验证不同人物、有言语/无言语、画外/电话/旁白、跨镜续说和少样本场景。人工审核新规划的时间分配；需要重新生成的视频按用户操作提交，不自动产生批量视频任务。

## 10. 验收标准

- 两份示例 8 句的中位数按原始精度计算得到约 6.18 字/秒，陈默个人中位数约 6.61，代码中没有写死这些数字。
- 标记、取消、重新启用、任务重试和版本切换后，统计结果与合格记录一致，无重复计数。
- 归档副本及素材/音色替换不会污染原成片的说话人和音色版本归属。
- 同一人物在不同项目使用不同名字时，个人样本数及中位数按全库合并；同名不同人物保持独立。
- 人物改名、切换图片、替换参考录音不创建新的素材人物身份；重复导入的同一人物按明确映射归并，归档副本仍去重。
- 人物参考检索跨项目命中自身历史，提交给 LLM 时仍沿用当前角色名称、素材编号和剧情，不泄漏旧项目的剧情约束。
- 不用整个视频时长替代对白窗口，不重复计算跨镜整句，缺少窗口的记录不会伪装成精确语速。
- 无个人样本时能提供库级基准；有可靠参考音频时附加其数据；有个人样本后呈现个人统计及样本量。
- 15 字/秒等已人工认可数据继续可检索，不设未经依据的语速阈值自动删除。
- LLM 输入可追溯到本次统计版本和具体样本，原剧情、台词及素材归属不受历史内容污染。
- 分段缩短/延长时，Shot 边界、Beat、任务时长和帧数正确同步，总长重新汇总，目标总长及其他段不被改写。
- 测试保证数据和同步正确；实际规划质量通过人工查看新输出与后续成片验证，不用模拟 LLM 的测试声称已证明语速选择正确。

## 11. 规模判断

这是一项中等规模的数据与规划输入改造，主要工作在逐句结构化数据、身份/音色归属、样本生命周期及两类规划器的统一接入。生成工作流不需要重做。

建议先落地可追溯统计与数值上下文，再积累情绪细分数据。暂不引入固定加权公式、自动删除快语速样本、特定场景秒数或强制全片自动重规划。
