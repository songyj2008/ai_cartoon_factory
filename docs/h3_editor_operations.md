# H3 开场承接与参考移除

重启项目并刷新页面后，在分段全屏编辑器使用。

全屏编辑器新增“结束状态处理”下拉框和“一键准备并生成”。选择下拉框本身不执行任务；原有按钮仍可分别操作，“结束状态登记（手动）”中的按钮点击后立即执行。

展开“管理场景”可查看每个场景对应的分段并删除未使用场景。删除前会确认，后台在保存锁内重新检查使用情况与初态版本；仍有分段使用时无法删除。需要删除使用中的场景时，先将相关分段归属改为其他场景或“不加入”。同名场景在归属下拉框中标注分段数量或“未使用”。

- 未加入场景：保存当前稿 → 按右侧所选 LLM 规划时长并保存 → 提交视频生成。
- 已加入场景：优化提示词 → 应用并保存 → 规划时长并保存 → 按下拉框选择登记结束状态 → 提交视频生成。
- 选择“提取本段结束状态（LLM）”时重新调用 LLM，不因已有状态而跳过；选择“沿用上段（无变化）”时明确声明本段无状态变化。没有同场景上段时沿用场景初态，按无变化保存，不调用 LLM；首段的一键流程在初态待建立时先保存当前稿，调用现有 LLM 提取并保存场景初态，再继续优化和后续步骤，最终稿按所选方式沿用状态或重新提取结束状态。非首段遇到未建立初态时提示具体首段，不自动处理其他分段。
- 本页的人物状态优化、状态提取、时长规划及反馈修正统一使用右侧“本页面使用的 LLM”。单选固定使用该服务，多选仅在所选服务中调度；“跟随全局”读取全局默认服务，不使用各功能的独立路由覆盖。提交时冻结选择，纠正重试沿用该选择范围；一键流程启动后整条流程沿用启动时的页面选择。其他页面的配置不变。
- 时长规划单独优先 ChatGPT：所选服务包含 ChatGPT 时只使用 ChatGPT，不混用其他服务；未包含 ChatGPT 时使用所选其他服务。“跟随全局”先解析全局默认服务，再应用此规则。其他操作继续使用完整的页面选择范围。
- 每一步成功后才继续，失败保留已完成结果，并在浏览器中保存分段断点。关闭编辑器停止后续串联，已提交的后台任务继续保留。刷新或重新打开后不自动执行；点击重试时核对当前保存稿、提示词、参考素材、时长、开场输入状态、场景归属和 LLM 配置，未变化则从失败步骤继续，变化时显示原因并重新准备。结束状态提取结果本身不作为开场状态变化。已完成流程再次点击会重新准备并提交。旧版只有显示记录、没有可核验断点的情况，可单独点击标红步骤处理。

- 开场承接默认读取前一段保存稿；来源下拉可选该段具体视频的提交提示词。该来源不是实际画面识别。
- 承接主要用于同一场景：沿用上一段结束时明确的场景布局、人物状态与站位。当前稿静态站位冲突时按上一段修正；明确安排的走动、进出、坐下等动作从继承状态继续执行。新人物可按当前稿进场，镜外人物不强制入画。明确换场时正文不改，不套用旧场景。
- 同场景候选沿用上一段所选来源的场景参考图。双方各有一张不同场景图时，替换当前场景槽位的文件与用途，不追加两个冲突背景；多个场景无法唯一对应时报错。已有同一图片不重复加入，并同步 Subject/Picture 编号与定义。复用原图片文件，只在应用候选并保存后写入当前段；换场不导入。所选来源没有场景图、文件丢失或素材超限时明确报错。
- 来源明确仍在现场、尚未离场的人物由模型确认继续在场，并补入当前段缺少的人物图片及原站位。同一人物已有当前参考时，沿用来源人物图，保留目标素材槽位和剧情角色标识。角色标识优先于可复用的素材库身份，避免两个剧情角色共用素材时串绑。没有对白或未被当前镜头拍到不等于离场，可以保留在镜外；不强制入画，已离场或仅被提及的人物不导入。
- 承接回复的 `retain_character_asset_ids` 可列出目标稿已有及待补入的人物；程序只为选中的缺失人物新增素材。合法范围为提供给模型的全部人物参考，不包括背景或音频，未知 ID 仍报错。目标已有的人物不因未列入此数组而被删除。
- 仅为当前稿对白中实际发言的人物承接音色：优先采用来源中明确绑定到该人物的音色，否则采用来源人物携带的素材库声音。已有当前音色时保留其槽位并更新文件；缺失时补入。来源未提供对应音色时保留当前选择；不把上一段其他说话人的声音套用给当前人物，不为旁听者新增音频。台词原文、说话人及声音阶段仍受保护。
- 只调整衔接及直接冲突的场景、站位描述，不改剧情、对白、说话人和时间轴；沿用原文不计为修改，正文没有变化时显示无需调整。
- 点击承接生成后台候选，查看候选全文，应用到当前稿，最后点击顶部保存。离开后可读取上次候选。
- 移除图片先校验整体修改；任务概述仅提及的人物恢复普通姓名，所有对白保持。实际画面或首帧依赖仍需处理，不能自动删除剧情人物。
- 图片移除不连带删除人物音色。电话人物无需为了音色保留图片。
- 移除已绑定人物的参考音色时，同步清理对应的逐句音色引用和托管声音说明，保留台词、说话人、人物图片与时间轴，并为该人物设置本段禁用自动音色。后续承接也尊重此设置；可通过人物的自动音色选项重新启用。仍用于完整录音播放等非音色用途的引用不会被自动删除，需要先处理依赖。
- 本段上传替换人物音色时，新音频的文件路径和素材ID均可变化；提示词按唯一、明确的说话人绑定同步音频编号。角色ID优先于素材库身份，归属不同或无法唯一匹配时仍拦截。承接候选应用后再替换音色，也会先同步参考绑定再校验对白与时间轴，避免旧音色ID阻止保存。
- 正文、素材和开场约束一起保存。历史视频和当前选择保留；当前稿标记需要重新生成。
- 主体定义和参考关系统一使用精简格式，生成、保存、换图、排序、移除及承接时共用渲染规则。人物一致性和通用声音要求各写一次，音色归属放入主体定义，不再追加独立的长音色绑定区块。主体定义保留素材已有身份简介，优先使用 `identity_summary`，未设置时使用已有主体或图片描述；可用 `appearance_summary` / `reference_summary` 补充明确的外观或参考特征，不根据姓名编造信息。未安排入画的人物仍保留图片绑定，是否在场及站位按镜头描述执行。历史视频提交快照不批量改写，仅重建当前编辑稿的托管章节。
- 本版跨段 Shot 结构草稿和未上传文件需要先保存完成，再执行复合操作。承接不自动增删镜头、调整时间；按上述规则继承人物、场景与当前发言者音色，不导入视频。
- 单独改变参考素材不能代替删除人物剧情；无法可靠解析的声画结构会保留当前稿并报出问题。
- “读取当前稿”自动读取明确的人物字段：`画面人物` / `入画人物` 可使用当前参考的姓名、角色ID或 Subject 编号，支持中英文冒号；`visible_roles` 支持字符串数组或 Subject 列表；空镜支持 `无`、`无人物`、`无人`、`[]`。未知或重名人物明确报错，不再误读成空镜。对白内容与普通剧情提及不会作为完整入画名单推断。
- 未写人物字段时，可读取直接的镜头主体表达（如 `<Subject 1 > 正面近景`）和明确的 `<Subject 1> 画内对白`；不从视线目标、否定句或台词内容提取入画人物。省略逐镜场景选择时，只有当前绑定唯一且有场景ID的背景图才用作默认；多个背景仍需明确指定。

本地相关 H3 回归与 JavaScript 语法检查已执行；真实网页生成及浏览器交互仍需验收。全库测试尚未全部通过。

承接逻辑现已拆入独立的 `generation/pipelines/minimax_h3/continuity/` 模块，接口与边界见 [模块说明](h3_continuity_module.md)。新候选按稳定人物身份提供来源事实及原文引用，输出展开为本段独立的人物、场景和站位描述。新候选保存前核对来源版本；候选正文被手改后，旧状态失效，不覆盖用户稿。此模块相关六份回归共148项通过，未调用真实LLM或视频生成。


## 连续场景批量生成

顶栏“生成视频”打开全部分段分组页，使用已保存稿。勾选分段后批量分配连续场景及结束状态处理方式，支持单段覆盖。未分组需明确选“独立生成”。同场景可跨相邻编号，承接来源列显示实际同组前段；相同地点但不同时间请使用不同连续场景。可展开查看已有初态。新场景仅在启动时保存，没有初态时自动提取，未知事实不猜测。

点击“保存分组并一键生成”启动后台批次。本批统一沿用第一个勾选段已保存的视频渠道，目前支持 H3 工作流渠道（RunningHub/ComfyUI）。仅保存和处理勾选段的分组、提示词、时长、末态和视频提交；未勾选段完全跳过，不修改其分组或承接来源，不创建文字或视频任务。连续场景承接只读取前驱已保存状态，缺少或失效时明确提示阻塞分段，由用户决定如何处理，不自动重做前段。每个勾选段完成优化保存、时长规划、末态登记后立即提交视频，后段文字准备不等待前段视频提交或渲染。其他场景可独立推进。

“沿用”表示末态与输入状态一致，不禁止镜内临时动作。若模型记录的实际末态不同会报出冲突；可调整失败段的模式再点击“继续失败批次”。已完成状态登记后要换模式或更改分组，应重新打开分组页建立新批次。后台保存步骤和版本，正常失败续跑不重做已完成步骤。平台提交不确定时保留提交记录，不自动重发；需要先核对原平台任务。显示“视频已提交”不代表成片已经完成或画面已核验。

手动点击单段“重新生成视频”会调用现有“一键清空”：停止所有项目的文字及扩展视频任务。清空在新视频提交前执行，以免删掉刚创建的任务；清空失败则不提交。批量任务内部及编辑器的一键准备流程不调用全局清空，避免自我取消。已经发到远端的请求可能继续执行，但被清理的扩展任务结果不再回填。准备/提交均不会自动核验成片空间位置。
