# 网页 LLM 配置与视频反馈修正

## 使用

重启项目，更新并重新加载 `tools/chrome_prompt_bridge` 扩展（v0.2.0），刷新 LLM 网页。配置界面位于「设置 → 模型配置 → 网页 LLM / Chrome 扩展」。

复制本机后台地址和配对码到扩展侧边栏，为各服务绑定专用对话并启用连接。项目显示扩展在线后即可提交。扩展只连接本机 HTTP 服务；当前支持 DeepSeek、ChatGPT，豆包和千问为禁用的待适配条目。

路由优先级：本次选择 → 功能入口覆盖 → 全局默认。配置以安装目录为单位在本机持久保存。旧的剧情、Beats、提示词等入口保留 API 默认，需要手动切换为跟随全局或具体网页服务；新视频反馈修正默认跟随全局。

在分段全屏编辑器中，左侧素材、中间编辑器、右侧预览和反馈。预览选择本段最新已有文件的成片，使用同一次生成的提示词快照；缺少历史快照时提示手动填写原提示词。填写问题与期望效果后提交，完成后可查看原稿、修改说明与修正版，应用或保存并生成。

## 实现边界

- `services/web_llm_bridge.py`：服务目录、配置路由、SQLite 持久队列、单次领取凭据、成片快照和通用网页 LLM 等待。
- `ui/web_llm_routes.py`：同源本机 UI 配置/任务接口及 Bearer 配对的扩展接口。
- `ui/web_llm_ui.py`：共享服务选择控件、配置页、视频反馈面板和生命周期保护。
- `services/llm.py`：共享 JSON / 文本调用按入口分流；现有 API 路由保留原调用行为。
- `scripts/story_script/generate_beats.py`：独立 Beats SDK 调用接入同一配置。
- 扩展 `worker.js`：后台配对、按绑定服务领取、发送、恢复读取及回传。不会自动重新发送已领取的任务。
- 提示词修改、创作判断由 LLM 完成；本地代码只校验输出结构、关联版本和调用状态，不从一次视频问题生成运行时修复规则。

正文按纯文本和 JSON 处理，模型回复不作为代码执行。结果带任务编号，通用调用用 `data` 字段，提示词修正用 `changes` 和 `revised_prompt`。未完成任务即使浏览器或服务重启也不会重新自动领取，避免重复发送；超时后可取消并新建任务。

项目切换、分段切换和关闭弹窗使旧页面回调失效；应用前重新检查保存的提示词、素材和视频快照，并检查编辑器及未保存的参考素材是否变化。修正历史与输入快照保留在本机队列。

## 验证

后端测试覆盖路由优先级、成片历史、草稿快照、跨项目拒绝、原文缺失、并发领取、回传授权、重复/迟到回传、取消/超时、HTTP 本地闭环以及共享 LLM 分流。扩展测试覆盖输入草稿保护、只发送一次、按编号解析、任务恢复和回传、取消后拒绝结果。

网页选择器仍可能随服务改版变化。自动识别发送按钮失败时，扩展保留请求并提示手动发送；在扩展点击「读取本次回复」后继续回传。真实账户联调需要已登录且完成配对的 Chrome，模拟测试不代表网页账号端已验证。
