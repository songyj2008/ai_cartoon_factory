# H3 提示词职责与模式

共同语义合同仅维护在 profiles/h3_segment_planning_rules.md。Beat、单段规划、局部反馈分别追加任务专属要求，不向普通任务注入完整特殊发声协议。

- Beat 输出事件摘要和初版 Shots；完整且通过结构/对白校验的初版可直接复用，避免第二次导演创作。不完整计划仍需规划。
- 显式重新生成从当前底稿重新规划，不恢复旧 Shots。当前编辑稿优先于 Beat 和历史上下文。
- 场景人物初态、结束状态和全员取景记录仅供内部规划与核对。最终视频提示词在各 Shot 构图中表达必要的人物位置、姿势和可见关系，不追加独立的【场景人物占位】表；历史占位块在重新编译时移除，内部状态继续保留。
- 所有 H3 生成和重规划请求都要求每段总时长为 4–15 秒整数；Shot 内部可小数。固定时长与自动估时各自遵守当前模式，不存在草稿超限例外。
- 重新规划时长只替换时间数值；不修改镜头内容、台词或镜头数量。
- 新规划采用 dialogue/dialogues，可将原句拆为有 continues_previous 的跨镜片段。程序比较原文、主人、顺序及声源渠道；画内外可随构图改变。旧编号回复仍可被读取，但不再要求新请求使用单句单镜协议。
- H3 拆分保留对白原文和每段独立时长，不继承旧的平均分时、固定顶层场景和允许缩写约束。
- 反馈只改指定范围和直接冲突；声音/口型反馈可修相关声画描述。单次问题不再保存全局正则质检规则。
- 最终结构校验检查有时间的 Shots 连续覆盖总时长，拒绝间隙、重叠、非有限时间和不完整覆盖。
- 历史人工 OK 的提示词窗口仍是计划数据，不能冒充音轨实测；经验只作软参考。

文字规则简化不等于模型效果保证。后续成片对照应分别观察对白完整性、发声边界、听者口型和空间连续性。

每次提交给 LLM 的规划规则都要求每段总时长为4–15秒整数。若模型违规返回小数或超限结果，仍保留原始回复和阻止提交的诊断供人工修正；这属于错误结果保留机制，不是允许模型超限的规划规则。程序不擅自取整或压缩对白。

已保存提示词或当前编辑稿拥有当前素材清单，即使素材最初来自自动匹配。视频提交前重建工作流不得根据旧 Beat 的空匹配结果增删引用；只有未形成编辑稿的初次规划才使用自动匹配默认值。
