最新版本：0.4.44。当前千问网页显示单条输入上限 10000 字符；本次排查的完整请求长 13248 字符。扩展在新请求填入之前及未发送旧任务恢复时拒绝超限请求并回传明确错误，保留后台完整原文，不截断或自动改写。已经尝试发送的任务不会因新检查而重复发送。扩展全量 182 项测试通过。

长文本附件发送尚未实现，需要先核验真实千问 TXT 上传入口和完成回执。不要将 0.4.44 的长度保护理解为已经支持超长输入。

此前版本 0.4.43 的输入修复继续保留。用户于 2026-11-03 明确要求开放千问以便之后试用，后端 LLM 选择及扩展任务调度现已启用，manifest 包含仅 `https://www.qianwen.com/*` 的站点权限。本次未向真实网站发送测试请求，真实账号可用性仍待用户试用。v0.4.43 已移除 Slate 的 execCommand 写入路径，改为校验页面与任务后由浏览器输入事件填入原请求；需重新加载扩展并刷新千问，恢复旧版已损坏的编辑器。

## 已实现

- 后端服务目录填写千问主页，标签为“千问”，可在全局及各功能的 LLM 选择中勾选。现有默认服务不自动切换。
- 扩展精确匹配 HTTPS `www.qianwen.com`，不匹配根域、其他子域或相似域名。
- `qianwen.js` 只处理页面控件与消息证据，不包含剧情、角色、时长或视频工作流规则。
- `content.js` 使用千问输入框分支，保护草稿；确认整条用户消息后绑定路由。发送前持久保存记录，发送不确定及刷新恢复只读原任务，不重复提交。
- 页面通过新出现的路径、查询或 fragment 标识路由，保存为不透明路由键，不推测服务器会话 ID。初次主页发送可能延迟产生地址，因此不会提前绑定主页；完成回传和任务页清理沿用现有实现。
- 仅从助手最终回答提取结果，排除可识别的思考区域和用户消息；不使用全页文本兜底。检测到停止生成控件时不完成任务。最终结果仍严格校验任务编号、JSON 和数据结构。
- 在高级设置中可配置输入框、发送按钮、最终回答和已发送用户消息选择器；消息角色不存在时，必须先核验并配置对应选择器。
- `worker.js` 自动调度只遍历已启用服务。按服务声明、领取附件能力；千问不支持附件，禁止静默退化成文字任务。
- `heartbeat()` 可保存按服务能力表；旧版客户端的能力列表继续有效，无需数据库结构变更。

## 尚未验证的真实页面事实

已通过 Chrome 页面快照及用户提供的首页 HTML 确认：输入框是 Slate 编辑器，带 `data-slate-editor="true"`、`role="textbox"`、`contenteditable="true"`；发送按钮有 `data-session-switch-target="send-query"`、`aria-label="发送消息"`；空白首页的按钮禁用。“思考研究”控件的 `aria-pressed="true"`。仍未核实以下事实：

1. 长文本写入后，千问 Slate 编辑状态是否接受全部内容。
2. 唯一发送控件及普通点击能否在后台页提交。
3. 用户消息、思考区域、助手最终回答各自的 DOM 边界。
4. 开始与结束生成的准确页面信号。
5. 首次提交后的实际地址，以及刷新后能否通过保存的地址恢复原会话。

输入框和发送按钮选择器已有用户提供的真实 HTML 依据；回复区域的语义属性仍是保守识别契约，尚无真实回答 DOM 验证。离线测试通过不能证明真实账号已可用。

## 试用方法

1. 重启项目后台，使新版服务目录生效，再刷新项目页面。
2. 在 Chrome 扩展管理页重新加载 `tools/chrome_prompt_bridge`，确认版本为 0.4.44，按浏览器提示批准新增的千问站点权限。关闭千问页面的 F12 开发者工具，然后刷新页面，避免旧版 DOM 写入残留。
3. 打开并登录 `https://www.qianwen.com/`；刷新已打开的任务网页。
4. 在所需功能的 LLM 选择中勾选“千问”，提交一条短文字任务试用。首次建议并发设为 1。
5. 如提示输入框、用户消息或最终回答无法识别，在扩展高级设置中核对对应选择器；保留原任务页面及诊断记录。千问视频附件仍禁用。

0.4.40 曾在自动审批拒绝后保留禁用状态；该状态已由本次用户明确要求开放试用的改动替代。配对认证、documentId、binding_epoch、lease、任务结果和历史记录保持原有规则。
