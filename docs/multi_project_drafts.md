# 项目、草稿与后台任务

一个项目可创建多个独立草稿。每个草稿保存自己的小说原文、Beats、Segments、提示词、连续场景记录和视频历史。归档后只读。人物与场景素材库仍可共享。

## 项目切换

浏览器窗口使用各自的 Gradio 会话记录当前项目、草稿及项目内上次选择。自定义 API 携带同一会话与页面运行目录；旧页面请求和当前窗口选择不一致时返回 409。已开始的后台任务固定到原目录，切换窗口或项目不会改变其归属。会话选择保存在后端进程内，重启后由持久化的最近选择重新初始化。

## 视频提交

普通生成、重新生成视频不会清空任务中心，也不会取消其他项目的工作。任务中心的“一键清空”仍是用户主动执行的全局停止操作。

RunningHub 使用统一的账号提交锁和跨项目、跨草稿的任务计数；H3 与 LTX 共用名额。名额不足时保存到各自本地队列，按持久化的入队时间分配。云端只等待提交回执，后台 worker 继续同步未选中的项目与草稿。单个应用后端进程负责该队列。

## 长篇小说

超过 `config.json` 中 `novel_chunk_chars`（默认 6000 字符）的原文，按引号外的自然文本边界分批输入模型，保留全部原文。邻接文字仅作为阅读上下文，不作为本批摘录。Beat、Shot、对白和时长仍由模型决定，本地只校验结构及摘录覆盖，汇集结果并重新编号，不改写剧情。

每批成功后保存到原有任务私有检查点；重试可复用相同输入的已完成批次。单段对白或无边界文本过长时明确报错，不截断原文。分批结果仍受各模型上下文与输出上限约束。

## 任务历史

任务中心始终列出进行中、需处理和待应用的文字任务；已应用、取消、失败的历史任务每页 50 条，可向前后翻页。服务器分页后返回，避免只显示最近 100 条造成旧任务失踪。分类筛选作用于当前页；任务保留期限沿用原规则。
